## What we're building

A dashboard builder: an app chrome (top navbar, docking sidebar, docking context bar) around a drag-and-resize widget canvas fed by pluggable datasources. The chrome, notifications, error and loading UI came first; the dashboard follows in phases: reading (done), editing and viewing tools, more widgets and data, persistence, then real datasources.

A datasource that connects to an outside service is an optional plugin (Azure SQL, MongoDB, AWS and Google so far). A build has one only when `plugins.json` lists it, and users create connections to it in the app. Telemetry such as Sentry is an integration, which is to follow the same list (06 §3). The default list is empty, so a fresh build reads local files only.

## Locked decisions

| Decision         | Choice                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Backend          | None at start. Dashboards load and save through one plain module (`listDashboards`, `getDashboard`, `saveDashboard`); phase 5 rewrites its bodies to call HTTP. No repository interface until a second implementation exists ([08](plans/done/08-structure-cleanup.md))                                                                                                                                                     |
| Persistence      | JSON files in `/data/dashboards` and `/data/templates` are the seed; a saved copy and the unsaved draft live in localStorage. The document carries `schemaVersion`, and `migrateDashboard` upgrades old files ([08](plans/done/08-structure-cleanup.md))                                                                                                                                                                    |
| Layout           | Blocks: grid, collapsible row and tabs (tabs may hold rows), each grid its own react-grid-layout; no `container` widget ([07](plans/07-dashboard-model.md))                                                                                                                                                                                                                                                                 |
| Charts           | `@mantine/charts` (Recharts) as default; the registry allows uPlot later                                                                                                                                                                                                                                                                                                                                                    |
| User             | Placeholder via a `CurrentUser` context, no auth                                                                                                                                                                                                                                                                                                                                                                            |
| Time range       | Scoped: dashboard → section → widget, each inheriting unless it sets its own, with a time zone and one shared `now` per refresh. Viewers change it in the URL; edit mode saves it. Template variables: schema slot now, UI in phase 4 ([07](plans/07-dashboard-model.md))                                                                                                                                                   |
| Responsive       | Desktop builder (`md+`), smaller screens view-only, layouts stored per breakpoint                                                                                                                                                                                                                                                                                                                                           |
| Undo/redo        | Yes: the dashboard document is one immutable slice edited via immer, `zundo` temporal middleware; one undo step per user action (a drag, a resize, a menu action, a field on blur) ([07](plans/07-dashboard-model.md#3-modes))                                                                                                                                                                                              |
| Structure        | A single Vite app with package-shaped folders (`app`, `features`, `plugins`, `shell`, `core`, `ui`, `lib`), imports one way, enforced by oxlint; no monorepo yet, but each folder can become a package ([08](plans/done/08-structure-cleanup.md)). Today's layout is in [architecture.md](../../docs/architecture.md)                                                                                                       |
| Code style       | Vercel composition patterns and react-best-practices; the agent skills in use are listed in [AGENTS.md › Skills](../../AGENTS.md#skills)                                                                                                                                                                                                                                                                                    |
| Optional plugins | Datasource plugins for outside services are in a build only when `plugins.json` lists them, `[]` by default. Unlisted ones have no code in `dist`; listed ones load each type's code lazily. Add to build edits the file from the dev server, or commits it from the live site with the user's GitHub token. For datasources this replaces the runtime integration config (Oct 24, [11](plans/done/11-optional-plugins.md)) |
| Secrets          | Typed into the app and kept in memory. Saved only when asked, encrypted with a passphrase (PBKDF2-SHA256 at 600k iterations, AES-GCM) and tied to the settings they were saved with. Never in dashboards, exports, URLs, query keys or logs ([research](research/browser-secrets.md))                                                                                                                                       |
| Relay            | SQL Server and MongoDB, which browsers can't reach, go through `relay/`: a stateless Node server in the repo that needs a token beyond localhost ([11](plans/done/11-optional-plugins.md))                                                                                                                                                                                                                                  |
| Sentry           | The first telemetry integration, in the product's Integrations area                                                                                                                                                                                                                                                                                                                                                         |
| Context bar      | Help, general information and notifications; tools such as Inspect open in right-side drawers ([07](plans/07-dashboard-model.md))                                                                                                                                                                                                                                                                                           |
| Navigation       | Navbar area picker (may become a workspace or tenant switcher), sidebar with Favorites and Recent, breadcrumbs; app-level tabs later ([07](plans/07-dashboard-model.md))                                                                                                                                                                                                                                                    |

## Roadmap

Each phase ends with Storybook stories, tests and a short review against the coding rules. Plans are numbered in build order; some belong to a phase, others cut across phases. Status per item is in [tasks.md](tasks.md).

**Order (Sep 30).** Phase 3 started with the edit MVP ([07](plans/07-dashboard-model.md) stages 1 and 2), which is built but not yet accepted. Next is [08 Structure cleanup](plans/done/08-structure-cleanup.md): it fixes the gate (lint, the React Compiler setup, the invisible edit drawer), adds real-browser tests that also close 07 stage 2's acceptance checks, and moves the code into package-shaped folders. Then 07's drag and resize measurement, the viewing tools (07 stage 3), 06 Sentry's error reporting and source maps, and the Integrations foundation, which must be in before Sentry becomes an integration (06 §3) and before phase 4's datasource manager offers integrations. Phases 4 to 6 each add their part. Oct 6: phase 3 is done (07 stages 1–3 and 08); 06 Sentry §1–2 is next. Oct 24: [11 Optional plugins](plans/done/11-optional-plugins.md) is done. It replaces the Integrations foundation for datasources, and 06 §3 is to follow its `plugins.json`.

**Changes from the Sep 22 plan:**

- Mantine `Splitter` replaced `AppShell` and the custom resize handle.
- oxlint replaced ESLint; a local plugin adds the style rules.
- bulletproof-react layers replaced the light feature folders (02).
- The time range lives in the URL, and the registries are static maps built in `app/` instead of `registerWidget()` calls (05).
- The color scheme is applied by an inline script in `index.html` before first paint.
- Phase 6 was called "Integrations"; it's renamed "Real datasources" so it isn't confused with the Integrations area (06).
- Sep 29: integrations get their own registry and config, and Sentry becomes its first entry instead of a feature of its own. They're enabled by config, not feature flags ([research](research/integrations.md)).
- Sep 29: the time range is scoped (dashboard → section → widget) instead of global; layout blocks replace the `container` widget; the context bar is for help and general information, and Inspect is a right-side drawer ([07](plans/07-dashboard-model.md)).
- Sep 30: the edit MVP moves ahead of 06 Sentry and the Integrations foundation. After a review: queries are cached one entry per datasource query, the time model gets a time zone, undo steps follow user actions, Sentry reports query errors from the query cache, and integration manifests are split from their code ([07](plans/07-dashboard-model.md), [06](plans/06-sentry.md)).
- Sep 30: after a review of the edit MVP, 08 comes before the rest of 07. Package-shaped folders replace the bulletproof-react layers; the dashboard document becomes one flat type with `schemaVersion`; the repository port becomes a plain module until a second implementation exists; localStorage keys lose their `.v1` suffix; browser tests run through Storybook's Vitest addon ([08](plans/done/08-structure-cleanup.md)).
- Oct 24: datasources that reach outside services became optional plugins chosen at build time in `plugins.json`, instead of integrations enabled by a runtime config. Their secrets are typed into the app and kept in a passphrase vault rather than only in a backend, and a relay in the repo runs SQL Server and MongoDB queries. Azure SQL and AWS moved from phase 6 into 11, with MongoDB and Google ([11](plans/done/11-optional-plugins.md)).
- Sep 30: planning moved from `docs/` to `.agents/planning/` (roadmap, tasks, plans, research); `docs/` holds only the human-facing docs, including the new [architecture.md](../../docs/architecture.md), which now holds the stack and the project structure.

## Open questions and risks

| Item                        | Why it matters                                                                                                                                                | Default if undecided                                                                                                                                                                                                               |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Recharts with large series  | Recharts slows past ~10k points                                                                                                                               | Aggregate in the datasource to the widget's resolution; reduce points (LTTB) only for drawing; add a uPlot widget only if needed                                                                                                   |
| Search scope                | Spotlight over dashboards only, or also widget contents and datasources                                                                                       | Dashboards and routes now; widgets in phase 3                                                                                                                                                                                      |
| Undo scope                  | Undo for layout only, or also options and datasource edits                                                                                                    | The whole document; `timeRange` and selection excluded from the temporal slice                                                                                                                                                     |
| Who changes the plugin list | There's no auth, and the list decides what code the site ships                                                                                                | `plugins.json` in the repo: Add to build on the live site needs a token that can write to the repository (11)                                                                                                                      |
| Third-party integrations    | Runtime plugins (module federation) need matching shared dependency versions and run outside code in the app                                                  | Not supported; an entry's `loadRuntime()` can point at a remote later without changing its callers                                                                                                                                 |
| Backend                     | Persistence needs a server, and the relay (11) covers SQL Server and MongoDB but keeps nothing; TanStack Start in SPA mode and a separate API are the options | Decide later; the phase 5 API stays a mock until then                                                                                                                                                                              |
| Auth                        | A shared proxy for real datasources must not be open to anyone who reaches the site; the relay needs a token beyond localhost                                 | Decide later (Better Auth, Clerk or WorkOS); required before phase 6 ships                                                                                                                                                         |
| Phase order                 | Whether the backend and auth move into phase 5, ahead of real datasources                                                                                     | Decide later                                                                                                                                                                                                                       |
| Widget editor and palette   | The overlay drawer covers the tiles being edited                                                                                                              | Built: a right-side drawer for the palette and options, a main-pane query editor (07 open decision 1). Proposed: a docked editor pane that resizes the grid ([tasks.md › Edit UI polish](tasks.md#edit-ui-polish-not-planned-yet)) |
