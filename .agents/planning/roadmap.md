## What this phase builds

The dashboard builder becomes a small application platform the clinic app can start on: a short cleanup, packages, storage you can switch, data you can show, edit and extend, navigation with record tabs and Studio, and a node builder. The table widget improves in parallel. The clinic app (rhb-cdss, its own repo) starts when P6 is done and uses all of it.

## The concepts this phase introduces

- **Fixed foundations and swappable capabilities.** React, TanStack Router and Query, Mantine, Zustand with Immer and Zundo, Zod, react-grid-layout and TanStack Table with Virtual are built on and never swapped. Everything else is a capability with a default provider, listed in the capability catalog.
- **Workspace, Studio and context bar** are three concepts. The workspace is where people work with open records, dashboards and pages. Studio is the area where the app is set up: navigation, pages, collections, schemas, bindings and graphs. The context bar shows information about the current view, including the data it uses.
- **One application schema in four layers:** the app definition (manifest, collections, schemas, bindings, dashboards, graphs), deployment settings (`plugins.json`, environment), user preferences (open tab ids, pins, columns, language, theme) and runtime data (records, query results). One store owns the app definition, and every editor sends it commands.
- **The data catalog:** a datasource is where data is reached; a collection is a group of records; a schema (JSON Schema) describes its fields; a binding says what a page or widget uses; provenance records the original source and the current storage. A schema edit is never a database migration.
- **Storage is a provider:** this browser, files, or Convex. App data (workspace, Studio work, preferences) and records are both stored through it, and both must work locally and download. Data stays with its collection: a field added to a collection is stored where that collection lives.
- **Every feature is a capability with swappable providers:** storage, search, export, sign-in, the assistant, datasources and telemetry. Switching a provider changes no component.
- **Record types are described by data and pure functions,** never by hooks in a registry.

## Locked decisions

| Decision         | Choice                                                                                                                                                                                                                                                                                                                             |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Backend          | No hand-written server. Storage is a provider: the browser, files or the Convex plugin, on Convex Cloud's free plan (Oct 26)                                                                                                                                                                                                       |
| Packages         | The private `@rhb-cdss` scope. rhb-cdss links a local checkout; GitHub Packages under the RHB-CDSS organisation once CI or a deploy needs it                                                                                                                                                                                       |
| Persistence      | JSON files are the seed. Saved copies and drafts move from localStorage onto the storage provider in P3. Documents carry `schemaVersion` with migrations, and a `revision` for conflict checks                                                                                                                                     |
| Layout           | Blocks: grid, collapsible row and tabs (tabs may hold rows), each grid its own react-grid-layout; no `container` widget ([07](https://github.com/deneslee/mantine-dashboard-builder/blob/0e400dd/.agents/planning/plans/07-dashboard-model.md))                                                                                    |
| Charts           | `@mantine/charts` (Recharts) as default; ECharts or uPlot can extend or replace it                                                                                                                                                                                                                                                 |
| Graphs           | React Flow by default; a graph kind may use another editor, such as GoRules' for decision graphs                                                                                                                                                                                                                                   |
| User             | Placeholder via a `CurrentUser` context; sign-in becomes a provider                                                                                                                                                                                                                                                                |
| Time range       | Scoped: dashboard → section → widget, each inheriting unless it sets its own, with a time zone and one shared `now` per refresh ([07](https://github.com/deneslee/mantine-dashboard-builder/blob/0e400dd/.agents/planning/plans/07-dashboard-model.md))                                                                            |
| Responsive       | Desktop builder (`md+`), smaller screens view-only, layouts stored per breakpoint                                                                                                                                                                                                                                                  |
| Undo/redo        | One immutable document per editor, edited via immer, `zundo` temporal middleware; one undo step per user action ([07](https://github.com/deneslee/mantine-dashboard-builder/blob/0e400dd/.agents/planning/plans/07-dashboard-model.md#3-modes)). The app definition gets the same store pattern                                    |
| Structure        | Package-shaped folders become packages in P2; imports one way, enforced by oxlint. Today's layout is in [architecture.md](../../docs/architecture.md)                                                                                                                                                                              |
| Code style       | Vercel composition patterns and react-best-practices; the agent skills in use are listed in [AGENTS.md › Skills](../../AGENTS.md#skills)                                                                                                                                                                                           |
| Optional plugins | In a build only when `plugins.json` lists them, `[]` by default; listed ones load each type's code lazily; Add to build from the dev server or the live site ([11](https://github.com/deneslee/mantine-dashboard-builder/blob/0e400dd/.agents/planning/plans/done/11-optional-plugins.md)). The Convex plugin joins the list in P3 |
| Secrets          | Typed into the app and kept in memory. Saved only when asked, encrypted with a passphrase and tied to their settings. Never in dashboards, exports, URLs, query keys or logs ([research](https://github.com/deneslee/mantine-dashboard-builder/blob/0e400dd/.agents/planning/research/browser-secrets.md))                         |
| Relay            | SQL Server and MongoDB, which browsers can't reach, go through `relay/`: a stateless Node server that needs a token beyond localhost. It stays as it is ([11](https://github.com/deneslee/mantine-dashboard-builder/blob/0e400dd/.agents/planning/plans/done/11-optional-plugins.md))                                              |
| Sentry           | The first telemetry integration, following `plugins.json` ([06](https://github.com/deneslee/mantine-dashboard-builder/blob/0e400dd/.agents/planning/plans/06-sentry.md) §3); it comes in a later phase                                                                                                                             |
| Context bar      | Help, general information, notifications and the read-only Data tab ("Data used by this view"); working tools such as Inspect open in docked panels                                                                                                                                                                                |
| Navigation       | From the navigation manifest: areas in the sidebar, with Studio, Integrations and Settings pinned at the bottom; record tabs; views as a sidebar group or tabs. The navbar's area picker may become a workspace switcher                                                                                                           |
