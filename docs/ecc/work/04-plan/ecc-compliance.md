# ECC compliance check of the plan

2026-11-22. This compares [04-plan.md](../04-plan.md) and its detail files with what each ECC skill or command actually requires. The source is ECC 2.2.3: `~/.claude/plugins/cache/ecc/ecc/2.2.3/{skills,commands,agents}`, read on 2026-11-22.

Verdict per row: ✅ follows · ⚠️ partly · ❌ missing.

Paths that differ from a skill's default on purpose, because the playbook sets them (`docs/ecc/work/…` instead of `plans/`, `docs/adr/`, `docs/impacts/` or `docs/retro/`), are marked **override**. They are not counted as defects.

## 3. Fixes to apply to the plan (proposed, not applied)

1. **Per-step blueprint fields.** For each step in the detail files, add one line each: brief, model tier, rollback, and branch name.
2. **A rollback and compatibility window for S3.5, S5.7 and S5.8.** For S5.8 this means migrating existing draft keys.
3. **Command fixes:**
   - S1 uses `/ecc:orch-fix-defect` for G-036, and plain edits plus `verification-loop` for the test and tooling cuts.
   - S4 drops `orch-refine-code`.
4. **One council question per conflict** (or C1–C4 as one).
5. **Approval gates written into S0:** ADR writes, a new `CONTEXT.md`, and a stated path for acceptance briefs.
6. **Register triage.** A "Triage" section maps every G-001…G-036 row to a stage or to `wont-fix` with a reason. Add a Phase 6 re-audit to S8, with `audit-docs.py` as the exit.
7. **Mark manual steps** that plan-orchestrate will report as BLOCKED.
8. **One deletion per `/refactor-clean` run**, with the CAUTION tier for lazy modules.
9. **Decision for the user:** keep ECC's 80 % coverage rule, or override it per U8.
10. **Add** `git-workflow`, `conventional-commit-review` and `safety-guard` to "Every step", and `module-regression` after S3.

## 4. Is a custom skill or plugin needed?

**What ECC does not cover:** none of these skills runs a full step of this repo's plan in sequence. That sequence is:

1. read the step from `04-plan`;
2. `change-impact` before;
3. the right `orch-*` command, or a manual step;
4. `vp run check:*`;
5. `orch-review`;
6. `change-impact` after;
7. update the G-row status and the plan.

`plan-orchestrate` only prints commands, and it blocks every step that is not an `orch-*` command. Each skill also writes to its own default path (`plans/`, `docs/adr/`, `docs/impacts/`, `docs/retro/`), and the playbook overrides those by hand every time.

**Options:**

| Option                                                                                             | Cost                            | Covers                                                                                         |
| -------------------------------------------------------------------------------------------------- | ------------------------------- | ---------------------------------------------------------------------------------------------- |
| A. Add a "path overrides plus per-step sequence" section to the playbook                           | lowest                          | Paths only. The sequence still relies on the model reading the playbook.                       |
| B. A project skill `.claude/skills/restructure-step/SKILL.md`, invoked as `/restructure-step S2.3` | low; one Markdown file, no code | The step sequence, path overrides, the repo's check commands, and the register and plan update |
| C. A plugin (skill, hooks, commands)                                                               | high                            | It only pays off across several repos, and this is one repo                                    |

**Recommendation: B, after running `ecc:skill-scout` once to confirm nothing equivalent exists.** ECC's own rule is to check `skill-scout` before creating a skill. Keep it project-local and delete it in S8, or keep it if the workflow should outlive the restructure. A plugin (C) is not justified for one repository.
